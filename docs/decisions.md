# Журнал решений

Почему сделано именно так. Новое решение — новая строка сверху раздела; отменённое не удалять, а пометить.

## Инфраструктура

| Дата | Решение | Почему |
| --- | --- | --- |
| 2026-11-21 | Несжатый дамп — только внутри контейнера, в `BACKUP_DIR` попадает готовый архив | Папка будет облачной: временный файл не должен туда синхронизироваться |
| 2026-11-20 | Бэкап ждёт `pg_isready` и не считает пустой дамп успешным | После перезагрузки контейнеры стартуют в любом порядке; в `pg_dump \| gzip` ошибка терялась — получился пустой бэкап |
| 2026-11-17 | **Без VPS и домена:** платформа на компьютере владельца, HTTPS через quick-туннель cloudflared | Владелец решил запускать пилот бесплатно; облачные бесплатные хостинги «засыпают» и разносят части по сервисам |
| 2026-11-17 | API сам узнаёт адрес туннеля из метрик cloudflared и перенастраивает ботов | Адрес quick-туннеля меняется при каждом перезапуске; ручная перенастройка ломала бы ботов |
| 2026-11-17 | Main Mini App в @BotFather не используем | Там адрес задаётся вручную, а у туннеля он меняется. Вернуться при домене |
| 2026-11-17 | Бэкап — отдельный контейнер `pg_dump` раз в сутки в `BACKUP_DIR` | Требование «копии вне сервера» без внешних сервисов: папка может быть облачной |
| 2026-11-16 | Всё на одном сервере, без внешних хостингов фронтенда | Требование владельца |

## Роли и доступ

| Дата | Решение | Почему |
| --- | --- | --- |
| 2026-11-21 | Игры, призы и шансы редактирует суперадмин в боте клуба; логика общая с пультом (`services/prizes.py`), владельцу платформы приходит уведомление о каждой правке | Клуб настраивает акцию сам, а владелец сразу видит странные настройки вроде приза с шансом 90% |
| 2026-11-20 | «🙋 Гости» доступны всем сотрудникам клуба, телефон — последние 4 цифры | Админу у кассы нужно найти гостя; полный номер не нужен (требование безопасности) |
| 2026-11-17 | Три уровня: владелец платформы (`.env`, все клубы) → суперадмин клуба (один, назначает владелец) → админ (назначает суперадмин) | Модель владельца; в требованиях прежнее «Суперадмин» = владелец платформы, теперь термины разведены |
| 2026-11-17 | Назначение сотрудников — встроенным выбором пользователя Telegram (`request_users`) | Не нужно знать и вводить Telegram id |
| 2026-11-17 | Отдельный бот платформы (пульт), а не скрытые команды в ботах клубов | Управление всеми клубами не смешивается с чатом одного клуба; клубы подключаются без кода |

## Продукт и данные

| Дата | Решение | Почему |
| --- | --- | --- |
| 2026-11-25 | Три игры: колесо, стаканчики (1 из 6, без перемешивания), кейс (лента призов); у каждой свои призы, лимит и выключатель; у новых и старых клубов сначала включено только колесо | Владелец выбрал механики по примерам промо-игр; кейс знаком игрокам компьютерных клубов. Скретч-карта отклонена владельцем. Игры без призов не должны появляться у гостей сами |
| 2026-11-25 | Гостю не показываются шансы — только цвет редкости (красный ≤ 5%, синий ≤ 20%, зелёный — чаще); цвет считается сам из шансов | Решение владельца; клубу не нужно отдельно размечать редкость |
| 2026-11-25 | Стаканчики: все 6 разыгрываются в момент выбора, гость видит настоящее содержимое остальных | Честно и просто: выбор не влияет на вероятность, хранить «раскладку» заранее не нужно |
| 2026-11-25 | Mini App всегда тёмный, акцент — цвет клуба; секторы колеса окрашены по редкости | Решение владельца: современный игровой вид независимо от темы Telegram; цвет приза везде значит одно и то же |
| 2026-11-25 | Старые адреса `/api/wheel` и `/api/spin` оставлены | Mini App, открытый до обновления, продолжает работать |
| 2026-11-21 | Нельзя выключить последний приз игры или последний приз с промокодом; максимум 12 призов в игре; нельзя включить игру без приза и выключить последнюю включённую | Игра не должна сломаться или обещать гостям приз, которого нет |
| 2026-11-20 | Регистрация в Mini App: согласие через API, номер — только `requestContact` → бот | Проверка «контакт свой» остаётся на сервере; Mini App не принимает номер напрямую |
| 2026-11-20 | Оформление клуба в `clubs.branding` (JSONB), картинки — файлы на сервере | Гибко без миграции на каждое поле; ссылки на файлы Telegram содержат токен бота |
| 2026-11-20 | Свой префикс промокодов у клуба; старые коды работают с полным префиксом | Брендинг кодов без поломки выданных |
| 2026-11-20 | Сброс оформления не трогает префикс | Иначе ручной ввод старых кодов без префикса сломается |
| 2026-11-20 | Правила до 3500 символов; длинные старые правила — отдельным сообщением | Правила + согласие должны помещаться в 4096 символов Telegram |
| 2026-11-20 | Удаление приза = `active = false` | На приз ссылаются прошлые игры и промокоды |
| 2026-11-20 | Очистка игровых данных клуба — с подтверждением названием клуба; удаления клуба целиком нет | Необратимое действие; удаление клуба — отдельная, более опасная функция |
| 2026-11-20 | Сети клубов (этап 4) **не объединяют гостей** | Принцип 2 «полная изоляция»; общий лимит на сеть — только отдельным решением |
| 2026-11-17 | Статус подписки выводится из дат, фон лишь обновляет поле | Решение «можно ли играть» верно в любой момент |
| 2026-11-17 | Отсрочка 3 дня действует и после пробного периода | Клубу нужно время оплатить |
