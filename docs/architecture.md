# Архитектура

Платформа мини-игр лояльности: у каждого компьютерного клуба свой Telegram-бот с Mini App (колесо фортуны), один общий сервер обслуживает всех.

## Поток запроса

```
Telegram (боты клубов, бот платформы, Mini App у гостя)
   │  HTTPS
   ▼
cloudflared (quick-туннель, https://….trycloudflare.com)
   ▼
Caddy :80  ── /app/*   → статика Mini App (собранный miniapp/dist)
           ── /api/*   → API Mini App          ┐
           ── /tg/*    → вебхуки ботов         ├─ api:8000 (FastAPI + aiogram)
           ── /health  → проверка              │
           ── /media/* → картинки клубов       ┘
                                                  ▼
                                              PostgreSQL
backup: pg_dump + картинки → BACKUP_DIR раз в сутки
```

Всё запускается одной командой Docker Compose на компьютере владельца (VPS и домена пока нет). Порты наружу не открыты: только `127.0.0.1`.

## Компоненты

| Где | Что |
| --- | --- |
| `backend/app/main.py` | FastAPI: роуты, раздача `/media`, фоновые задачи (подписки, туннель) |
| `backend/app/routes/telegram.py` | `POST /tg/{bot_id}` — вебхуки ботов клубов |
| `backend/app/routes/platform.py` | `POST /tg/platform` — вебхук бота платформы (объявлен раньше `/tg/{bot_id}`) |
| `backend/app/routes/miniapp.py` | `/api/me`, `/wheel`, `/spin`, `/prizes`, `/rules`, `/consent` |
| `backend/app/bots/` | боты клубов: гость (`handlers.py`), админ-панель (`admin.py`), настройка (`setup.py`), реестр (`registry.py`) |
| `backend/app/platform_bot/` | бот платформы (пульт): клубы, оформление, подписка, сброс данных |
| `backend/app/services/` | бизнес-логика без Telegram: колесо, коды, погашение, роли, подписка, оформление, гости |
| `miniapp/src/` | React + Vite + TypeScript: колесо, призы, правила, регистрация, сканер |
| `deploy/` | Caddy, образ web, compose для рабочего запуска, скрипт бэкапа |

## Ключевые механизмы

**Клуб определяется только по боту.** Вебхук: `bot_id` в адресе + секрет в заголовке `X-Telegram-Bot-Api-Secret-Token` → запись `club_bots` → клуб. Mini App: `?bot=<id>` в адресе → заголовок `X-Bot-Id` + подпись `initData`, проверенная токеном этого бота. `club_id` от клиента не принимается.

**Все боты в одном процессе.** Один диспетчер aiogram для ботов клубов (`bots/dispatcher.py`), отдельный — для бота платформы. Экземпляры `Bot` кэшируются в `registry`, токен расшифровывается только в памяти.

**Адрес туннеля меняется при каждом перезапуске.** API раз в минуту спрашивает его у cloudflared (`/quicktunnel` на метриках) и при смене перенастраивает вебхуки и кнопку Mini App у всех ботов (`services/tunnel.py`). Первый опрос после старта перенастраивает всегда. Ботов трогаем, только когда наш `/health` открывается по новому адресу 90 секунд подряд (иначе Telegram запоминает «Failed to resolve host»); если хоть один бот не настроился, настройка повторяется с паузой 1, 2, 4, затем 5 минут.

**Результат спина — только на сервере.** Транзакция с блокировкой гостя (`FOR UPDATE`): подписка → лимит → выбор сектора через `secrets` → запись игры и промокода → commit. Mini App лишь докручивает колесо.

**Фоновые задачи в API:** статусы подписок раз в 10 минут; адрес туннеля раз в минуту (раз в 10 секунд до первого успеха).

## Режимы запуска

| Режим | Что запущено | Туннель смотрит на |
| --- | --- | --- |
| Рабочий | `docker compose -f docker-compose.yml -f deploy/compose.server.yml up -d` | Caddy (`web:80`) |
| Разработка | `docker compose up -d` (db + api) + `npm run dev` + свой `cloudflared` | Vite `127.0.0.1:5173`, он проксирует API |

Одновременно оба режима не запускать: каждый переставляет вебхуки на себя. Подробно — [operations.md](operations.md).
