# Архитектура

Платформа мини-игр лояльности: у каждого компьютерного клуба свой Telegram-бот с Mini App, где гости играют в колесо, стаканчики и кейс. Один общий сервер обслуживает всех.

## Поток запроса

```
Telegram (боты клубов, бот платформы, Mini App у гостя)
   │  HTTPS
   ▼
cloudflared (quick-туннель, https://….trycloudflare.com)
   ▼
Caddy :80  ── /app/*   → статика Mini App (собранный miniapp/dist)
           ── /api/*   → API Mini App          ┐
           ── /tg/*    → вебхуки ботов         ├─ api:8000 (FastAPI + aiogram)
           ── /health  → проверка              │
           ── /media/* → картинки клубов       ┘
                                                  ▼
                                              PostgreSQL
backup: pg_dump + картинки → BACKUP_DIR раз в сутки
```

Всё запускается одной командой Docker Compose на компьютере владельца (VPS и домена пока нет). Порты наружу не открыты: только `127.0.0.1`.

## Компоненты

| Где | Что |
| --- | --- |
| `backend/app/main.py` | FastAPI: роуты, раздача `/media`, фоновые задачи (подписки, туннель) |
| `backend/app/routes/telegram.py` | `POST /tg/{bot_id}` — вебхуки ботов клубов |
| `backend/app/routes/platform.py` | `POST /tg/platform` — вебхук бота платформы (объявлен раньше `/tg/{bot_id}`) |
| `backend/app/routes/miniapp.py` | API Mini App (таблица ниже) |
| `backend/app/bots/` | боты клубов: гость (`handlers.py`), админ-панель (`admin.py`), игры и призы клуба (`prize_editor.py`), настройка (`setup.py`), реестр (`registry.py`) |
| `backend/app/platform_bot/` | бот платформы (пульт): клубы, бот, игры, призы, подписка, правила, QR, оформление, сброс данных |
| `backend/app/services/` | бизнес-логика без Telegram: игры (`wheel.py`), призы и редкость (`prizes.py`), коды, погашение, роли, подписка, оформление, гости, статистика |
| `miniapp/src/` | React + Vite + TypeScript, всегда тёмный интерфейс: лобби игр, колесо, стаканчики, кейс, призы, правила, регистрация, сканер |
| `deploy/` | Caddy, образ web, compose для рабочего запуска, скрипт бэкапа |

### API Mini App (`/api`)

| Метод | Что |
| --- | --- |
| `GET /me` | клуб, гость и шаги регистрации, доступность акции, список игр (`games`: включена, лимит, `next_play_at`), оформление |
| `POST /consent` | согласие с правилами из Mini App |
| `GET /games/{game}` | призы игры для показа: название, эмодзи, пустой ли, **редкость** (без весов) |
| `POST /play/{game}` | сыграть; для стаканчиков тело `{"choice": 0…5}`; ответ — приз, промокод, `next_spin_at`, для стаканчиков `layout` (что было под каждым) |
| `GET /wheel`, `POST /spin` | старые адреса колеса (= `/games/wheel`, `/play/wheel`) |
| `GET /prizes` | мои промокоды со статусами |
| `GET /rules` | правила акции |

`game` — `wheel`, `cups` или `case`; другое значение — 422.

## Ключевые механизмы

**Клуб определяется только по боту.** Вебхук: `bot_id` в адресе + секрет в заголовке `X-Telegram-Bot-Api-Secret-Token` → запись `club_bots` → клуб. Mini App: `?bot=<id>` в адресе → заголовок `X-Bot-Id` + подпись `initData`, проверенная токеном этого бота. `club_id` от клиента не принимается.

**Все боты в одном процессе.** Один диспетчер aiogram для ботов клубов (`bots/dispatcher.py`: редактор игр и призов → админ → гость), отдельный — для бота платформы. Экземпляры `Bot` кэшируются в `registry`, токен расшифровывается только в памяти.

**Результат игры — только на сервере.** `services/wheel.py::play`: транзакция с блокировкой гостя (`FOR UPDATE`) → подписка → игра включена → лимит этой игры → выбор приза через `secrets` по весам → запись игры и промокода → commit. Колесо и кейс — один розыгрыш, Mini App только докручивает анимацию до него. Стаканчики — сервер в момент выбора разыгрывает все 6 и отдаёт гостю выбранный.

**Подписка не останавливает игры сама.** Неоплата — только пометка «не оплачено» для владельца. Играть можно, если доступ клуба включён (`clubs.status = active`) и подписка не отменена старой командой; доступ отключает и возвращает владелец платформы в пульте.

**Гость не видит шансов.** API отдаёт редкость приза (`services/prizes.py::rarity`): красный ≤ 5%, синий ≤ 20%, зелёный — чаще.

**Адрес туннеля меняется при каждом перезапуске.** API раз в минуту спрашивает его у cloudflared (`/quicktunnel` на метриках) и при смене перенастраивает вебхуки и кнопку Mini App у всех ботов (`services/tunnel.py`). Первый опрос после старта перенастраивает всегда. Ботов трогаем, только когда наш `/health` открывается по новому адресу 90 секунд подряд (иначе Telegram запоминает «Failed to resolve host»); если хоть один бот не настроился, настройка повторяется с паузой 1, 2, 4, затем 5 минут.

**Фоновые задачи в API:** статусы подписок раз в 10 минут; адрес туннеля раз в минуту (раз в 10 секунд, пока ждём готовности нового адреса).

## Режимы запуска

| Режим | Что запущено | Туннель смотрит на |
| --- | --- | --- |
| Рабочий | `docker compose -f docker-compose.yml -f deploy/compose.server.yml up -d` | Caddy (`web:80`) |
| Разработка | `docker compose up -d` (db + api) + `npm run dev` + свой `cloudflared` | Vite `127.0.0.1:5173`, он проксирует API |

Одновременно оба режима не запускать: каждый переставляет вебхуки на себя. Подробно — [operations.md](operations.md).
