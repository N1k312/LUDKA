- [x] Создать тестового бота в @BotFather

### Шаг 2. База данных
- [x] Модели SQLAlchemy для 11 таблиц из требований

### Шаг 3. Подключение ботов
- [x] Шифрование токенов (Fernet)
- [x] Создание клуба: проверка токена через `getMe`, сохранение, установка вебхука с секретом, кнопки Mini App, описания и команд

- [x] Определение клуба по боту
- [x] Консольные команды суперадмина (`python -m app.cli`): клубы, призы, бот, сотрудники, перенастройка вебхуков
- [x] Туннель cloudflared для разработки

**Проверка:** тестовый бот отвечает на `/start` от имени клуба.

### Шаг 4. Вход гостя

- [x] Согласие с правилами акции и на обработку данных, запись `consent_at`
- [x] Команда `/rules` — правила акции в боте
- [x] Генерация QR-кода для печати у кассы (`app.cli make-qr`)

**Проверка:** новый гость проходит регистрацию, запись появляется в `guests`.

### Шаг 5. API для Mini App
- [x] Проверка `initData`: подпись токеном этого бота и свежесть `auth_date` (бот — из `?bot=` в адресе Mini App и заголовка `X-Bot-Id`)
- [x] `GET /api/me`: гость, статус согласия, время до следующего спина
- [x] `GET /api/wheel`: сектора колеса клуба (без весов)
- [x] `POST /api/spin`: проверка подписки и лимита, выбор сектора через `secrets`, создание промокода — всё в одной транзакции с блокировкой гостя
- [x] `GET /api/prizes`: мои промокоды со статусами
- [x] `GET /api/rules`: правила акции
- [x] Генератор промокодов: формат `GG-XXXXXX`, без похожих символов, уникальность
- [x] Отправка промокода гостю сообщением в боте

**Проверка:** тесты, включая двойной спин одновременно — проходит только один.

### Шаг 7. Админ-панель в боте
- [x] Меню видно только сотрудникам из `club_staff` этого клуба (`/admin`, в меню команд — только у них)
- [x] Ввод промокода вручную и через сканер QR Telegram (Mini App в режиме `?scan=1` → `web_app_data`)
- [x] Ответы: «действителен», «уже погашен», «истёк», «не найден»
- [x] Кнопка «Погасить» — атомарно, чтобы два админа не погасили один код дважды
- [x] Уведомление гостю «Приз получен»
- [x] Журнал `redemption_log`, включая неудачные проверки
- [x] Ограничение неудачных проверок (защита от перебора): 10 «не найден» за 15 минут

**Проверка:** промокод от гостя гасится админом, повторное погашение не проходит.

### Шаг 8. Подписка и безопасность
- [x] Статусы подписки: trial → active → past_due → canceled, с автоматическими переходами по датам (фоновая проверка раз в 10 минут)
- [x] Консольные команды суперадмина: `extend-subscription` (с записью оплаты), `cancel-subscription`, `list-payments`
- [x] Без подписки нельзя крутить колесо, но выданные промокоды можно погасить
- [x] Токены и телефоны не попадают в логи (вырезаются из итоговой строки, включая трейсбеки) и во фронтенд
- [x] Автотесты изоляции: админ клуба Б не гасит код клуба А, гость клуба А не видит призы клуба Б, чужой код отвечает «не найден», `club_id` из запроса игнорируется
- [x] Тест на одного человека в двух клубах

**Проверка:** все тесты зелёные.

### Шаг 9. Рабочий запуск на своём компьютере (без VPS и домена)
- [x] Caddy: собранный Mini App на `/app/`, прокси API и вебхуков (`deploy/Caddyfile`, `deploy/web.Dockerfile`)
- [x] HTTPS через quick-туннель cloudflared; API сам узнаёт адрес туннеля и перенастраивает ботов при его смене
- [x] Запуск одной командой: `deploy/compose.server.yml`, автоподъём после перезагрузки
- [x] Ежедневный бэкап базы в папку `BACKUP_DIR` (OneDrive / Google Drive / другой диск)
- [x] Включить автозапуск Docker Desktop и отключить сон компьютера
- [ ] Указать `BACKUP_DIR` в облачной папке
- [x] Инструкция по подключению клуба: [deploy/connect-club.md](deploy/connect-club.md)

**Проверка:** бот клуба-пилота работает с компьютера-сервера, после перезапуска туннеля всё восстанавливается само.
