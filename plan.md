# План разработки

Разбивка задач по шагам на основе [requirments.md](requirments.md). Каждый шаг заканчивается тем, что можно запустить и проверить. Выполненные пункты отмечаются `[x]`.

## Этап 1 — MVP

### Шаг 0. Подготовка
- [x] Установить инструменты (Python, Node.js, Git, Docker + WSL 2, cloudflared, VS Code, DBeaver, Telegram)
- [x] Создать тестового бота в @BotFather
- [ ] Купить домен и VPS (можно позже, к шагу 9)

### Шаг 1. Каркас проекта
- [x] Структура папок: `backend/`, `miniapp/`, `deploy/`
- [x] Git-репозиторий, `.gitignore`, `.env.example`
- [x] FastAPI-приложение с проверкой `/health`
- [x] PostgreSQL в Docker Compose
- [x] Настройки из `.env`: ключ шифрования, домен, URL базы
- [x] pytest, первый тест

**Проверка:** `docker compose up` поднимает базу и API, тест проходит.

### Шаг 2. База данных
- [x] Модели SQLAlchemy для 11 таблиц из требований
- [x] Миграции Alembic (применяются автоматически при старте контейнера)
- [x] Уникальные индексы: `(club_id, telegram_id)`, `(club_id, phone)`, код промокода
- [x] Составные внешние ключи `(club_id, id)`: база не даёт связать данные разных клубов
- [x] Заполнение тестовыми данными: клуб-пилот, призы, веса

**Проверка:** таблицы видны в DBeaver.

### Шаг 3. Подключение ботов
- [x] Шифрование токенов (Fernet)
- [x] Создание клуба: проверка токена через `getMe`, сохранение, установка вебхука с секретом, кнопки Mini App, описания и команд
- [x] Роут `/tg/{bot_id}`: проверка секрета, передача обновления в aiogram
- [x] Определение клуба по боту
- [x] Консольные команды суперадмина (`python -m app.cli`): клубы, призы, бот, сотрудники, перенастройка вебхуков
- [x] Туннель cloudflared для разработки

**Проверка:** тестовый бот отвечает на `/start` от имени клуба.

### Шаг 4. Вход гостя
- [x] `/start` с параметром `desk`: приветствие и кнопка «Играть»
- [x] Запрос номера телефона (`request_contact`) с проверкой, что контакт принадлежит самому гостю
- [x] Согласие с правилами акции и на обработку данных, запись `consent_at`
- [x] Команда `/rules` — правила акции в боте
- [x] Генерация QR-кода для печати у кассы (`app.cli make-qr`)

**Проверка:** новый гость проходит регистрацию, запись появляется в `guests`.

### Шаг 5. API для Mini App
- [x] Проверка `initData`: подпись токеном этого бота и свежесть `auth_date` (бот — из `?bot=` в адресе Mini App и заголовка `X-Bot-Id`)
- [x] `GET /api/me`: гость, статус согласия, время до следующего спина
- [x] `GET /api/wheel`: сектора колеса клуба (без весов)
- [x] `POST /api/spin`: проверка подписки и лимита, выбор сектора через `secrets`, создание промокода — всё в одной транзакции с блокировкой гостя
- [x] `GET /api/prizes`: мои промокоды со статусами
- [x] `GET /api/rules`: правила акции
- [x] Генератор промокодов: формат `GG-XXXXXX`, без похожих символов, уникальность
- [x] Отправка промокода гостю сообщением в боте

**Проверка:** тесты, включая двойной спин одновременно — проходит только один.

### Шаг 6. Mini App
- [x] Проект на React, Vite и TypeScript, подключение `telegram-web-app.js`
- [x] Экран колеса: анимация с замедлением до сектора от сервера, вибрация
- [x] Таймер до следующего спина
- [x] Экран «Мои призы»: промокоды с QR и статусами
- [x] Экран правил
- [x] Заглушка «Акция временно недоступна» и «Сначала зарегистрируйтесь»
- [x] Тема Telegram (светлая и тёмная)
- [x] Мок-режим для разработки интерфейса в браузере (`/app/?mock`)

**Проверка:** полный путь гостя в Telegram на телефоне.

### Шаг 7. Админ-панель в боте
- [x] Меню видно только сотрудникам из `club_staff` этого клуба (`/admin`, в меню команд — только у них)
- [x] Ввод промокода вручную и через сканер QR Telegram (Mini App в режиме `?scan=1` → `web_app_data`)
- [x] Ответы: «действителен», «уже погашен», «истёк», «не найден»
- [x] Кнопка «Погасить» — атомарно, чтобы два админа не погасили один код дважды
- [x] Уведомление гостю «Приз получен»
- [x] Журнал `redemption_log`, включая неудачные проверки
- [x] Ограничение неудачных проверок (защита от перебора): 10 «не найден» за 15 минут

**Проверка:** промокод от гостя гасится админом, повторное погашение не проходит.

### Шаг 8. Подписка и безопасность
- [ ] Статусы подписки: trial → active → past_due → canceled, с автоматическими переходами по датам
- [ ] Консольные команды суперадмина: продлить подписку, записать оплату
- [ ] Без подписки нельзя крутить колесо, но выданные промокоды можно погасить
- [ ] Токены и телефоны не попадают в логи
- [ ] Автотесты изоляции: админ клуба Б не гасит код клуба А, гость клуба А не видит призы клуба Б, чужой код отвечает «не найден»
- [ ] Тест на одного человека в двух клубах

**Проверка:** все тесты зелёные.

### Шаг 9. Выкладка на сервер
- [ ] VPS, домен, DNS
- [ ] Docker Compose для продакшена: API, Postgres, Caddy
- [ ] HTTPS через Let's Encrypt
- [ ] Сборка Mini App, раздача статики
- [ ] Ежедневный бэкап базы вне сервера
- [ ] Инструкция по подключению клуба, включая шаг с Main Mini App в @BotFather

**Проверка:** бот клуба-пилота работает с сервера.

### Шаг 10. Пилот
- [ ] Подключить реальный клуб, напечатать QR
- [ ] Собрать отзывы, исправить ошибки

## Следующие этапы

Подробные требования к каждому этапу пишутся перед его началом.

- **Этап 2 — панель владельца:** самостоятельное подключение бота, брендинг, редактор призов и шансов, управление админами, статистика, QR-постеры с метками источника.
- **Этап 3 — вовлечение:** слоты и другие игры, уведомления, рассылки, реферальные спины.
- **Этап 4 — масштаб:** автооплата и тарифы, сети клубов, динамический QR, интеграции с системами учёта клубов, Row-Level Security.
